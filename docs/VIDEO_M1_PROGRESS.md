## 使用新增能力

```sh
npm run dev:video
```

投送影片后，在“播放反馈”区域使用“连接与传输诊断”“重新检查连接”“导出诊断”。电影和音乐仍通过明确操作交接；影视默认开关保持关闭。

### 查看与导出诊断

诊断区展示本次会话时长、最近指令及接受/失败结果、查询时间和连续失败次数、GET / HEAD / Range 次数、当前/峰值读取路数、拒绝次数、最后响应状态及范围、累计提供的数据量。

“已提供数据”统计真正交给 HTTP 响应流的字节。HEAD 和尚未交出的预读数据不计入；重复 Range 会累计，因此数值可大于影片大小。它不是播放进度，也不能证明电视收到数据或正确解码。

可根据证据缩小排查范围：

| 观测 | 可判断的边界 |
| --- | --- |
| 最近指令未确认完成 | 先检查控制阶段；不自动重试 Play |
| 指令已接受、仅 HEAD 或数据量为零 | 尚无影片数据交付证据；检查接收端、地址、网络与防火墙 |
| 已提供数据、电视未回报播放 | 已到取流阶段；仍需现场检查解码、音轨与电视提示 |
| 返回 503 | 当前会话已达到读取上限；响应含 Retry-After，记录接收端的并发模式 |
| 返回 416 | 对方请求了不可满足的字节范围 |

“导出诊断”打开系统保存框，取消不会误报保存成功。报告使用明确字段清单，包含版本、播放阶段、受限媒体参数、指令结果和传输计数；不包含文件名/路径、设备标识、IP、媒体 URL、授权令牌、原始错误文本或账号凭据。文件采用临时文件写入后原子替换，只允许 `.json` 后缀。

报告对应点击时的会话快照。停止后仍可导出；开始新影片后，旧会话 ID/代际会被拒绝。诊断不建立持久化历史，也不会在后台自动上传。

### 失联与地址变化

后台状态查询失败后按 2 / 4 / 8 / 16 / 30 秒上限退避；失联不会重发 SetAVTransportURI 或 Play。明确的“重新检查连接”可绕过等待，重新读取设备描述、核对当前设备 ID 和网卡路由，再查询播放状态。

如果电视地址变化，先“重新搜索设备”，再检查连接。一个描述可能包含多个播放端，重查按原设备 ID 精确匹配，并保留网卡绑定，不会误选同描述中的另一台设备。

若原地址已经属于其他设备，关闭旧影片授权并标记已脱离，不向其他设备发送 Stop。若电脑本机地址与本次影片地址不一致，显示网络变化，等待明确停止、重新准备与播放；不会静默改写正在使用的 URL。设备不可达时保持未知状态，需要恢复网络或关闭应用后重新建立会话。

电视回报 TRANSITIONING 时显示等待播放反馈；短暂 STOPPED / NO_MEDIA_PRESENT 保留授权，避免跳转或缓冲断流。M0 的片尾处理继续要求明确停止，不加入自动连播。

## 读取与取消边界

每个影片授权最多 8 路同时读取，包含文件打开/定位阶段与响应生命周期；超额立即返回 `503` 和 `Retry-After: 1`。视频读取使用每块 64 KiB、最多两块排队的有界通道，不将整片读入内存。该上限不等同于进程 RSS 上限，系统网络缓冲等资源仍需高码率实测。

文件读取任务独立观察停止/退出和客户端断开。停止后丢弃尚未交出的排队数据，释放文件和读取许可；文件已经读完但 HTTP 响应尚未被客户端消费时，也可回收。旧音乐 HTTP 路径保持原行为。

## 包内工具检查

开发/CI 可对实际 Mac 应用包运行：

```sh
node scripts/verify-video-bundle.mjs \
  "src-tauri/target/aarch64-apple-darwin/release/bundle/macos/小米音乐投送.app" \
  aarch64-apple-darwin
```

脚本检查主程序与 FFprobe 的真实可执行文件架构、固定来源清单、包内声明、工具版本与许可输出，再清空 PATH，用包内工具解析仓库内真实的小型样片。Mac 包先验证资源签名，再对去签名的临时副本与固定来源比对；不修改实际应用包。自检是仓库构建工具，安装后的应用运行不依赖 Node 或开发机 PATH。

Windows 预览工作流仅允许在 GitHub hosted 临时 runner 上静默安装到随机路径。它拒绝已有同名安装或运行进程，验证实际安装目录的 EXE/FFprobe 后卸载并清理；不在开发者电脑执行安装测试，也不启动应用访问用户数据。该流程已加入代码，尚未实际运行 Windows CI。

工具分发材料与后续正式发布约束见 [FFprobe 来源与包验证](third-party/ffprobe.md)。普通音乐 Release 工作流与默认功能开关未因本轮改变。
