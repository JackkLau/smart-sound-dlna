# 小米音响 DLNA 本地音乐推流工具

在电脑上选择本地音乐，通过局域网推送到支持 DLNA 的小米 / 小爱音箱。带中文网页界面，支持发现音箱、导入音乐文件夹、上传音乐、播放队列、暂停 / 继续、切歌、进度与音量控制。

后端需要 Python 3.9 及以上，使用 Python 标准库。网页界面由 React 构建；首次使用和修改前端后，需要 Node.js 22+ 安装依赖并构建静态资源。构建完成后运行 Python 服务，无需额外的前端进程或在线 CDN。

## 开始使用

1. 将电脑和音箱连接到同一局域网。避免访客 Wi-Fi 或开启设备隔离的网络。
2. 在小爱音箱 App 中开启 **我的 → DLNA 音乐播放**。不同 App 版本入口可能不同，且需要音箱型号和固件本身支持 DLNA。小米官方指南列出的支持型号包括小米 AI 音箱、小爱音箱、小爱音箱 Pro、小爱音箱 Art、小爱音箱 HD；其他型号请以实际设置与官方说明为准。参见[小米官方 DLNA 使用指南](https://ics-resources.xiaomi.com/ics-resources/articles/6066c6ebe4801400d6db9c70.html)。
3. 在本项目目录运行：

   ```sh
   npm ci
   npm run build:ui
   python3 -m xiaomi_dlna
   ```

4. 浏览器会打开 `http://127.0.0.1:18200`。点击搜索设备，选择音箱，再选择本地音乐文件或导入电脑上的音乐文件夹，点击歌曲播放。

播放时，音箱会从电脑提供的 HTTP 地址读取音乐，因此电脑和本工具需要持续运行。关闭终端、电脑休眠或离开局域网都会影响播放。按 `Ctrl+C` 停止工具。

## 导入音乐

- **选择文件 / 拖放文件**：音乐上传到工具的数据目录，重启后仍保留。
- **导入文件夹**：输入本机文件夹的完整路径，递归索引音乐。不会移动或修改原文件，也不会重复加入同一路径的文件。隐藏文件夹与符号链接会跳过；移动或删除源文件后需重新导入有效位置。
- 为避免误读被替换的文件，工具记录文件标识。若源文件被替换，请重新扫描原文件夹；合法的替换文件会更新记录并保留歌曲 ID。
- 支持识别后缀：`MP3`、`FLAC`、`WAV`、`M4A`、`AAC`、`OGG`、`OPUS`、`WMA`、`AIFF`、`AIF`。

工具直接传输原始音频，不内置转码。后缀可导入不代表音箱一定支持文件中的编码、采样率或声道配置。建议先用常见 MP3 验证连接；遇到某首歌曲无法播放，可将它自行转换为音箱支持的格式后再导入。单文件最大上传 2 GiB，音乐库最多 20,000 首。

## 启动选项

```sh
# 启动时导入一个音乐文件夹
python3 -m xiaomi_dlna --music-dir "$HOME/Music"

# 更换端口，指定数据目录，不自动打开浏览器
python3 -m xiaomi_dlna --port 18201 --data-dir ./my-library --no-browser

# 多网卡 / VPN 环境：显式指定电脑的局域网 IPv4 地址
python3 -m xiaomi_dlna --interface 192.168.1.20 --advertise-host 192.168.1.20
```

`--interface` 指定设备发现所使用的本机 IPv4 地址；`--advertise-host` 指定音箱取流时访问的电脑 IPv4 地址。请替换为电脑实际的局域网地址，不要填写音箱地址或 VPN 地址。完整参数可运行 `python3 -m xiaomi_dlna --help` 查看。

默认数据目录为启动目录下的 `.data`；可用 `--data-dir` 更改。音乐索引存储在其中的 `library.json` 中，上传文件位于 `uploads` 文件夹。导入目录中的音乐保留在原位置。

## 连接问题

**搜索不到音箱**

- 确认音箱支持并已开启 DLNA，电脑和音箱处于同一局域网。
- 设备发现使用 SSDP / UDP 组播。访客网络、AP 隔离、部分 Mesh / 企业网络、VPN 或防火墙可能阻止组播；先关闭 VPN 或使用 `--interface` 指定局域网网卡。
- 可以在页面中手动添加**完整设备描述 URL**，例如从设备的 SSDP `LOCATION` 响应获取的地址。只填 IP 地址不够，路径和端口由设备决定，不应猜测。

**能发现设备，但无法播放**

- 允许 Python / 本工具通过系统防火墙接受局域网连接，并允许音箱访问工具使用的 TCP 端口（默认 `18200`）。
- 有多个网卡或正在使用 VPN 时，用 `--advertise-host` 指定音箱能够访问的电脑局域网 IPv4。
- 先尝试已知可播放的 MP3。某些音箱会接受播放命令，但不能解码特定音频格式。
- 电脑需保持唤醒。检查音乐文件是否仍在原位置，磁盘是否仍已挂载。

**进度、音量或自动切歌不可用**

这些功能取决于音箱提供的 UPnP 服务。程序轮询播放状态与进度；只有音箱正常报告歌曲时长、进度及结束状态时，才能可靠地自动切换下一首。手动点击停止不会触发自动切歌。

自动切歌根据播放状态与接近结尾的进度判断，并容忍音箱响应延迟。若音箱不报告时长、歌曲过短而未被采样到，或长时间断网，请使用手动切歌。检测到音箱改播其他来源时，本地队列会停止自动接管。

## 局域网访问范围

管理页面与控制 API 仅接受本机回环地址访问，控制操作还校验请求来源与会话令牌。音乐通过带随机会话凭据的媒体 URL 提供给局域网音箱，支持 HTTP `HEAD` 与单段 `Range` 请求，方便音箱读取和跳转。

服务不公开任意本地目录，只提供已导入的音乐。媒体 URL 在程序重启后失效；拿到有效媒体 URL 的局域网设备可在该会话中读取对应歌曲。无需将端口转发到互联网，也不建议这样使用。

## 测试

```sh
npm run build:ui

python3 -m unittest discover -s tests -v
```

测试包含本地模拟音箱的真实 HTTP / SOAP 交互、音乐库持久化、媒体字节范围、控制访问边界及播放状态切换。测试无需真实音箱，但实机的格式支持、局域网发现和固件行为仍需要在你的音箱上验证。

2026-10-22 验证：45 项 Python 测试全部通过；JavaScript 语法检查及严格 UI 静态审计通过。浏览器已检查导入文件夹、单文件上传、手动设备添加、播放/暂停/继续、搜索分页和键盘切换播放模式。独立 DESIGN 文档 lint 所需的工具包未缓存，受网络限制未运行；这不影响程序启动。

## React 前端开发

界面入口位于 `xiaomi_dlna/static/src/main.jsx`，页面、状态和交互由 `App.jsx` 的 React 组件管理。共享图标、弹窗和格式化函数与桌面 React 页面复用，Python 的 HTTP 控制令牌和媒体访问边界保持不变。不要恢复手工 DOM 页面构建或直接编辑 `dist/` 中的产物。

`npm run build:ui` 会生成 `xiaomi_dlna/static/dist/index.html`、`app.js` 和 `app.css`。Python 服务只提供构建后的文件；源码 HTML 由 Vite 处理，不能直接作为运行页面。前端改动后重新构建并刷新页面即可。
