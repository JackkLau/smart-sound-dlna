# 磁力下载器功能规划

面向在电脑上下载音视频、随后通过 DLNA 播放的用户。当前客户端使用 aria2，已有磁力任务、下载进度、暂停与继续、失败重试、重启后手动续传以及打开下载目录。本轮增加剪贴板识别。下表各项均为后续建议。

| 顺序 | 用户能完成什么 | 实现依赖与验收示例 |
| --- | --- | --- |
| 1．选文件和保存位置 | 获取种子信息，查看文件名、文件大小和所选总量，选择某一集、字幕及目标文件夹。也可从本地打开 .torrent 文件。 | 先让 aria2 暂停元数据生成的文件下载，再显示文件清单、设置所选索引并继续。用包含三集和字幕的测试种子，确认未点击开始前不传输正文，完成后所选文件可用，目录冲突时保留原文件。按文件选择仍可能需要传输跨文件的共享分片。 |
| 2．排队和限速 | 调整并发数，把今晚要看的影片移到等待队列首位，单独设置总下载、上传限速。 | 先持久化队列顺序和全局设置。并发数设为 1 时，下一项按新顺序启动；应用重启后恢复设置。后续再加定时限速。 |
| 3．批量添加 | 从多条磁力链接预览名称，勾选后一并添加，看到每一条的结果。 | 复用本轮的 BTIH 去重与原有添加接口。混合新链接、已在队列的链接和无效链接时，分别反馈；重试失败项不会重复创建成功项。 |
| 4．诊断停滞任务 | 在详情区区分正在获取种子信息、当前无已连接节点、Tracker 报错和磁盘写入失败，并能重试或校验文件。 | 接入引擎可提供的 Tracker、节点和错误数据；缺少证据时显示“暂未连接到节点”。用无节点和磁盘写入失败两个独立用例验证不同提示。 |
| 5．完成后投屏 | 从已完成任务中选择一个本地媒体文件，加入媒体库或选电视播放。 | 依赖文件清单和本地媒体导入。多文件任务只导入用户选中的文件，复用现有格式检测和设备选择。验收从选择一集开始，到电视播放该集结束。 |

第一阶段宜用本地测试种源验证 macOS 和 Windows 上从解析、选文件、写盘到续传的完整流程，再扩展批量和播放。现有剪贴板功能可识别多项并逐条选择，第三项规划的验收重点是批量提交和部分失败恢复。

qBittorrent 的官方功能列表列有种子内容选择、文件优先级、队列优先级和带宽调度。Transmission 列有限速和 Tracker 编辑。以上顺序是针对本项目的建议。引擎实现可查 aria2 手册中的 `pause-metadata`、`aria2.getFiles`、`select-file`、`aria2.changePosition` 及全局限速选项。
