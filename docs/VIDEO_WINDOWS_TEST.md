# Windows 影视预览测试

更新：2026-11-14。使用 GitHub Actions 的 `Video M0 preview` 工作流产物 `video-m0-preview-x86_64-pc-windows-msvc`。该包包含固定版本的 FFprobe；普通 Desktop builds / 正式 Release 安装包不包含本轮媒体工具，不应混用。

## 下载与启动

1. 在本次预览构建的 Artifacts 中下载 Windows ZIP，解压后运行其中的 NSIS `.exe` 安装包。安装前退出正在运行的旧应用，只保留一个实例；预览版沿用现有应用标识和本地数据目录。
2. 启动本次影视安装包，打开「影视」页。可选择本地影片，也可粘贴磁力链接并选择保存目录。下载完成后点「载入影片」。

电脑与电视连接同一局域网，电视打开 DLNA 接收功能。若系统首次询问防火墙访问，仅按家庭局域网的实际网络类型允许。测试期间电脑和应用保持运行；本轮还没有加入防休眠功能。

## 建议按顺序测试

| 步骤 | 预期 |
| --- | --- |
| 先播一首原有音乐 | 曲库、设备选择、音量、播放模式正常 |
| 切到影视并选择小型 1080p MP4 | 文件分析、电视选择和准备不停止音乐 |
| 明确切换并播放 | 电视出画出声；应用区分指令接受、文件读取和电视反馈 |
| 暂停、继续、停止 | 状态与实际电视一致；失败可以看到原因 |
| 重新播放后切回音乐 | 明确确认切换，原音乐曲库与本次运行的模式保留 |
| 选择主力 4K MKV/REMUX | 检查画质、声音、字幕、缓冲和拖动；音轨/字幕通过电视遥控器切换 |
| 退出并重新开启影视预览 | 最近影片和已确认位置保留，但不自动播放或续播 |
| 移除正在播放影片的历史 | 历史和位置移除，原文件及当前播放保留 |

Seek 仅按设备声明开放，实际文件能否跳转仍需验证；HTTP 数据量不代表播放位置。该包不做画质或音轨转码，不自动下一部，不开启自动续播。

遇到问题，在“播放反馈”里展开“连接与传输诊断”，必要时明确“重新检查连接”，再“导出诊断”。记录 Windows 版本、电视型号/固件、接收端名称、影片封装/编码/音轨、实际表现和复现步骤。导出的诊断不含文件路径、设备 IP、媒体授权地址或账号凭据。

## 构建范围

预览分支 `preview/video-*` 的推送和手动运行均会触发三平台预览验证。Windows 任务运行音乐/影视 Rust 测试、前端测试、真实 FFprobe 测试，并在临时 GitHub runner 安装、验证包内工具、卸载后才上传安装包。运行不代表 A7H 已通过解码或整片播放验收。
