# 小米音乐投送 · Rust + Tauri 2

Windows / macOS 桌面客户端，将电脑里的本地音乐通过 DLNA 投送到小米 / 小爱音箱。原生 Rust 负责设备发现、音乐库、HTTP 音频推流和播放控制，Tauri 2 提供桌面窗口与系统文件选择器。安装后的应用无需 Python、Node.js 或单独启动服务。

## 使用

1. 让电脑和音箱连接同一局域网，在小爱音箱 App 中开启 **我的 → DLNA 音乐播放**。小米官方列出的支持型号包含**小爱音箱 Pro**；具体入口随 App 版本可能变化。[小米官方说明](https://ics-resources.xiaomi.com/ics-resources/articles/6066c6ebe4801400d6db9c70.html)
2. 打开「小米音乐投送」，允许系统提示的本地网络访问。应用启动后自动搜索一次设备。连接成功后不再定时搜索，需要更换设备时点击「搜索其他音响」。
3. 选择音箱，再用「添加音乐」或「导入文件夹」打开系统选择窗口。点击歌曲即可播放。

支持暂停、继续、停止、上一首 / 下一首、进度、音量、顺序播放、单曲循环、列表循环。播放期间电脑必须保持唤醒且应用保持运行；退出应用会关闭推流服务。

**顺序播放**按完整曲库列表的顺序续播，到最后一首结束；列表循环会回到第一首，单曲循环重播当前歌曲。音响刚开始播放时短暂报告停止、或结束时清空进度，不会再让整条队列失去续播能力。自动切歌仍要求最近确认播放已接近结尾，手动停止、暂停、断连或其他控制器接管不会凭旧进度触发下一首。

### 小爱音箱 Pro 自动发现

- 对每张活动的 IPv4 网卡发送 SSDP 查询，覆盖 `MediaRenderer`、`AVTransport` 和通用设备响应，并重复查询一次。
- 读取音箱自己的设备描述，以 UUID 去重，优先显示小爱音箱 Pro，再显示其他小米设备。
- Pro 标识依据设备上报的名称 / 型号与小米厂商信息判断。改名或某些固件隐藏型号时仍显示可用设备，但不会猜测 Pro 型号。
- 使用发现音箱的网卡提供音乐链接，减少有线、Wi-Fi、VPN 并存时的选错网卡问题。
- 每约 2 秒读取当前音响状态；这与搜索整个局域网的设备发现不同。断连时保留选中音响并显示「自动重连中」，按 2、4、8、16、30 秒间隔持续重试，直到恢复或用户选择另一台；离线期间约每 30 秒重新发现设备，以更新同一音响的地址。点击断开的音响可立即重试。
- 播放、暂停等用户操作会优先中断后台状态查询，避免排在慢查询后等待；进度和音量查询各最多等待 1 秒，超时显示提示，不误判整台音响离线。
- 恢复连接不会自动播放或自动切换选中的设备。切换设备时会尝试停止本应用在原音箱上的播放。

自动发现能否在实际网络成功，仍取决于音箱固件、DLNA 开关和路由器组播设置。模拟设备通过不等同于真实 Pro 实机验证。

### 本地音乐

导入只索引原文件，不复制、不上传云端、不修改音乐。支持递归文件夹、中文与空格路径、重复导入去重、重启保留音乐库，最多 20,000 首。隐藏目录和符号链接 / Windows 重解析链接会跳过。源文件被移动、删除或替换后，请重新导入。

可导入 `MP3 FLAC WAV M4A AAC OGG OPUS WMA AIFF AIF`。目前直接传输原始文件，不内置转码；实际音频编码、采样率、声道兼容性由音箱决定。第一次连接建议用常见 MP3 验证。

点击歌曲的名称、文件名、格式或行内空白即可播放，也可点击播放图标。每行右侧的 **曲名** 和 **移除** 独立操作，不会触发播放。

点击 **移除 → 移出曲库** 仅移除曲库记录，原文件和下载的音频会保留，可重新导入；手动改过的曲名需要重新设置。移除当前播放的歌曲会先停止播放，移除其他歌曲不影响当前播放。

### 识别和修改曲名

新导入音乐会优先读取音频标签中的曲名，再尝试从文件名或视频标题提取（如 `歌手 - 晴天`、`《活着Viva》`）。无法确定时保留原标题。这是本地曲名信息提取，不上传音频，也不是根据旋律听歌识曲。

已有歌曲可点击右侧 **曲名** → **识别曲名**，核对结果或直接输入正确名称，再点击 **保存曲名**。修改会永久保存在曲库中，重新导入不会覆盖手动名称；原音频文件、当前播放和队列不受改名影响。同名版本可加入歌手或“现场版”等区别，避免语音点播歧义。

启用下方的小爱语音接入后，即可说 **“小爱同学，播放本地螺旋现场版”**，其中“螺旋现场版”换成保存的曲名。弹窗会显示对应示例，无需重新绑定音响。

## 小爱语音点歌

1. 先在主界面选择 DLNA 播放音响，然后打开左侧 **小爱语音**。
2. 点击 **登录小米账号**，在小米官方登录窗口完成登录。应用会自动完成小爱服务的签名授权、确认会话、更新账号状态并关闭登录窗口；若连接失败，可点击 **重试连接**。请选择绑定音响的账号。
3. 从账号设备列表选择接收语音的小爱，将它绑定到当前播放音响，点击 **开始接收指令**。
4. 说“小爱同学”，再说 **播放本地 + 歌名**，例如“播放本地晴天”。也支持“本地下一首 / 上一首 / 暂停 / 继续 / 停止 / 音量三十 / 单曲循环 / 列表循环 / 顺序播放”。

下方“测试指令”会通过同一指令处理层实际控制当前音响，不需要先登录账号，适合检查歌名匹配与 DLNA 控制。精确歌名优先；部分歌名只能匹配到一首时才会播放，多个匹配会提示补充歌名。切换主界面音响后，需更新语音绑定。

小爱并没有通用的 DLNA 语音点歌接口。本功能通过 **小米云端对话记录轮询**桥接到本地曲库，约每 3 秒读取一次，只执行启用后的新“本地”指令。语音识别仍由小爱完成，电脑不录音。普通聊天不执行、不保存；语音绑定和最近一次指令结果仅保留在内存，重启后仍需选择音响并明确开启接收。登录会话会自动恢复，但不会自动开始读取对话。该非官方接口可能随账号、固件或服务更新失效；连续读取失败后停止接收并显示原因，不保证与小爱原有语音回答完全无冲突。

如果官方网页登录不能取得会话，可展开高级接入，输入自己 `micoapi` 服务的 `userId=…; serviceToken=…` Cookie。不要使用米家其他服务的令牌。验证成功后同样使用系统凭据库保存；Cookie 不写入音乐库、日志或前端存储，不要向他人提供。官方登录窗口使用临时浏览会话且不能访问本地音乐 IPC。连接后可随时“停止接收”或“退出登录”。

### 重启与更新后保持登录

小米和 Bilibili 的有效服务会话分别保存在 **macOS 钥匙串 / Windows 凭据管理器**，使用稳定的应用标识，与安装目录、应用版本和曲库文件分开。重启或更新后自动读取并向服务端验证，通过后才显示已连接；网络暂不可用时保留缓存，可点击“重试连接”。会话过期时需要重新登录，不能绕过平台验证。

点击对应账号的 **退出登录** 会清除该账号的系统缓存；清除失败会显示错误，不会误报退出成功。不会保存小米密码、验证码或账号 `passToken`，也不会读取其他浏览器的登录数据。0.5.x 没有保存会话，因此首次升级到 0.6.0 后需要登录一次，之后有效会话即可恢复。系统凭据库锁定或要求授权时，请按系统提示处理。

## 从 Bilibili 建立本地曲库

1. 点击 **从 Bilibili 导入**，粘贴视频链接、BV / av 号或 b23.tv 短链接。支持 `zh-Hans` / `zh-Hant` 前缀与 `?p=` 分 P 链接。
2. 点击 **解析视频**，确认标题与作者，勾选一个或多个分 P，也可以全选此视频。
3. 点击 **下载并加入曲库**。可以关闭弹窗，主界面会显示排队、下载字节、入库结果；支持取消和失败重试。

**从收藏夹批量导入：**

1. 在导入弹窗切换到 **收藏夹**，粘贴带 `fid` 的收藏夹链接或 ID，点击 **读取收藏夹**。也支持 `medialist/detail/ml…` 链接。
2. 或在下方登录 Bilibili 后点击 **读取我的收藏夹**，选择并打开自己的收藏夹。私密收藏夹需要相应访问权限。
3. 每页显示最多 20 个视频；点击视频的 **选择音轨**，勾选单 P 或多个分 P，支持全选该视频。翻页保留选择，切换到另一个收藏夹会清空选择。
4. 点击 **下载选中音轨**。逐首下载入库，已在曲库或队列的内容会跳过并显示原因，未加入队列的选择会保留。失效视频直接显示不可用；预览超过 30 分钟时重新解析相应视频即可。

原生 Rust 解析视频信息，选择独立 AAC 音轨，保存为 **M4A**，不会下载视频画面或重新编码，不需要 Python、yt-dlp 或 FFmpeg。每批最多 100 首、最多排队 100 项，一次下载一项，单文件上限 1 GB。完成后校验 MP4 容器、原子保存，再把标题与来源写入曲库；未完成文件不会加入曲库，同一分 P 已入库时不会重复下载。任务列表保留本次运行最近 200 项，退出应用中断未完成任务；已完成音乐重启保留。

下载位置显示在弹窗“账号与保存位置”中，默认为应用数据目录的 `downloads/`。这里只支持普通投稿视频中可访问的独立 AAC 音轨，暂不支持直播、番剧或无独立音轨的视频。公开视频支持未登录解析和下载：客户端自动建立站点签发的匿名访客会话，并使用当前的 WBI 签名接口读取视频与音轨。匿名标识只留在本次运行的内存中，不会显示为“已登录”。需要登录权限的内容，可在官方页面登录 Bilibili，应用会自动确认会话并关闭登录窗口；连接失败时可点击“重试连接”。有效登录会话由系统凭据库保存，重启后验证并恢复，退出登录会清除。访问受限、风控、付费或区域限制会报告错误，不绕过权限。请仅保存你有权下载的内容。M4A 是否能在具体音响固件播放仍需实机确认，本版本不提供 MP3 转码。

接口参考：[MiService 的小米账号与服务签名交换](https://github.com/Yonsm/MiService/blob/master/miservice/miaccount.py)、[XiaoMusic 对话适配实现](https://github.com/hanxi/xiaomusic/blob/main/xiaomusic/conversation.py)、[MiService 的 MiNA 设备接口](https://github.com/Yonsm/MiService/blob/master/miservice/minaservice.py)、[yt-dlp 的 Bilibili 解析器](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/bilibili.py)。这些仅用于核对接口，不是运行依赖。

## 从安卓手机发送音乐（同一 Wi-Fi）

此功能从 0.7.1 起提供；上方固定下载入口会在三端构建全部成功后更新。

此功能先提供**免安装手机网页**：Bilibili 中选择视频 → 分享 → 复制链接 → 手机浏览器粘贴 → 电脑解析并下载。整段分享文案、`b23.tv` 短链接、BV 号和带 `p` 的分 P 链接均可发送。一次发送一个视频，多 P 可勾选多个音轨。

1. 在电脑应用点击 **手机发送 → 开启手机接收**。
2. 用手机相机扫描电脑显示的**二维码**，在常用浏览器（如 Chrome）打开，自动配对，**无需输入地址或连接码**。电脑有多个网卡时，在下拉框选择与手机同一网段的 IP。
3. 配对成功后收藏页面，或在浏览器菜单选择**添加到主屏幕**。下次直接打开即可；请使用同一个浏览器的普通模式，避免聊天应用内置浏览器。
4. 在 Bilibili 视频分享菜单复制链接，返回手机页面粘贴，点击 **发送并解析**。
5. 确认视频标题，勾选需要的音轨，点击 **在电脑下载选中音轨**。单 P 默认选中唯一音轨，多 P 默认选中链接指定的 P；每批最多 100 首。
6. 手机显示本次提交任务的下载进度，电脑主界面同步显示下载队列，完成后自动加入电脑曲库。关闭手机页面不影响电脑下载；取消与失败重试在电脑操作。

手机无需登录小米或 Bilibili；解析和下载使用电脑当前的 Bilibili 会话，公开视频继续支持匿名下载。应用重启后接收默认关闭，需在电脑再次开启，但手机配对会保留。**暂停手机接收**停止访问并保留配对，已接受的下载继续；**忘记手机并重新配对**撤销旧手机凭据并生成新二维码。换手机、清除浏览器数据或二维码过期时使用后者。

入口固定使用 **TCP 8998**，电脑 IP 不变时，收藏和桌面快捷方式地址跨重启保持一致。端口被占用会明确报错，不会悄悄换地址。配对二维码本地生成，包含十分钟有效的一次性随机凭据，成功后不能重复配对；手机在首次加载时移除地址片段，再通过同源请求兑换长期令牌。手机浏览器在 localStorage 保存令牌，电脑数据目录仅保存其 SHA-256 摘要，更新安装包不会更换保存位置。接收服务不随应用启动自动开启。

这是仅供可信家庭局域网使用的 HTTP 入口，不用于公网、公共 Wi-Fi 或端口转发。它只暴露解析、选中音轨下载及本次任务状态，不暴露登录态、电脑文件路径、完整曲库或播放控制；与音响的媒体服务使用不同端口及凭据。页面打不开时检查同一 Wi-Fi、访客网络隔离、VPN 和电脑防火墙的私人网络权限。

### 是否需要安卓应用

| 使用方式 | 是否需要 APK | 取舍 |
| --- | --- | --- |
| 复制 Bilibili 链接，在手机网页发送 | 不需要，本次实现 | 手机浏览器即可测试，电脑继续负责解析、账号与文件 |
| 在系统分享菜单直接点“小米音乐” | 建议做轻量 Android 配套应用，当前未提供 | 接收 `ACTION_SEND` / `text/plain` 和 `EXTRA_TEXT`，确认后调用同一接收接口；不必将整个播放器移植到手机 |
| 自动搜索同一 Wi-Fi 的电脑 | 原生应用可使用 NSD，当前网页未实现 | 本版使用固定地址加收藏/桌面快捷方式，避免反复扫码 |
| 安装 PWA 作为系统分享目标 | 有浏览器及安装条件限制 | `share_target` 必须是已安装 PWA，浏览器支持不统一，不能将普通局域网页面等同于系统分享目标 |

依据：[Android 官方接收分享数据文档](https://developer.android.com/develop/ui/compose/sharing/receive)、[MDN share_target 文档](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Manifest/Reference/share_target)。[Android NSD 官方文档](https://developer.android.com/develop/connectivity/wifi/use-nsd)提供原生应用的 DNS-SD 发现接口，普通网页不能直接调用 NsdManager。本版按用户选择保留免安装网页，不注册系统分享菜单，也不需要 Android SDK、移动端登录或云端中转。局域网 HTTP 页面添加的是浏览器快捷方式，不宣称是可安装 PWA 或系统分享目标。

安卓验收建议：使用 Chrome 打开接收页，验证短链接分享文案、普通单 P、`p=2` 多 P、重复提交、关闭页面后电脑继续下载、首次扫码免输码、收藏恢复、暂停后重新开启、重启后恢复配对、忘记手机后旧令牌失效。真实手机与路由器上的连通性需要现场验证，自动化本机 HTTP 测试不能替代这一项。

## 开发运行

需要 Node.js 22+、Rust stable 和对应平台的 Tauri 2 构建环境：

- **Windows 10 / 11**：Microsoft C++ Build Tools（Desktop development with C++、Windows SDK）和 Microsoft Edge WebView2。
- **macOS 11+**：Xcode / Command Line Tools。Apple Silicon 和 Intel 均有打包目标。

详见 [Tauri 2 官方环境配置](https://v2.tauri.app/start/prerequisites/)。

```sh
npm ci
npm run dev
```

界面位于 `frontend/`，无前端构建框架或开发服务器。通过 `core.invoke` 调用 Rust 原生命令；直接用浏览器打开 HTML 不具备控制功能。

若本项目存在 `.tools/cargo` 与 `.tools/rustup`，启动脚本会使用项目内 Rust 工具链；否则使用系统 PATH 中的 Rust。

## 打包

在对应平台执行：

```sh
# 当前系统的默认安装包
npm run build

# Windows：NSIS 安装程序
npm run build -- --bundles nsis

# macOS：应用与 DMG
npm run build -- --bundles app,dmg
```

产物位于 `src-tauri/target/release/bundle/`。macOS 可额外安装 `x86_64-apple-darwin` 或 `aarch64-apple-darwin` Rust 目标，然后传 `--target` 构建对应架构。

若 macOS 的 DMG 装饰阶段被 Finder / 已打开的镜像占用，先退出临时镜像里的应用并推出该镜像，再执行 `CI=true npm run tauri -- bundle --bundles dmg`。这是 Tauri 自带的无界面打包模式，跳过 Finder 窗口装饰。

`.github/workflows/desktop.yml` 在每次代码推送（所有分支及标签）、Pull Request 或手动运行时，自动执行 Windows x64、macOS Intel、macOS Apple Silicon 的原生测试和打包。默认分支 `master` 的推送构建中，三端作业全部成功后，会校验 EXE / DMG 格式、统一文件名、生成 SHA-256 并自动发布 GitHub Release；上述固定下载入口随完整发布更新。任意平台失败不会发布半成品，也不会替换上一套可用安装包。同一分支的新推送会取消仍在运行的旧构建。

分支、标签和 PR 的测试包仍可在 **Actions → 对应构建记录 → Artifacts** 下载，保留 30 天，需登录 GitHub；正式发布到 Releases 的安装包无需登录即可下载。

| 构建产物 | 系统 | 安装包 |
| --- | --- | --- |
| `xiaomi-music-x86_64-pc-windows-msvc` | Windows 10 / 11 x64 | 解压后运行 `.exe` 安装程序 |
| `xiaomi-music-aarch64-apple-darwin` | macOS Apple Silicon | 解压后打开 `.dmg` |
| `xiaomi-music-x86_64-apple-darwin` | macOS Intel | 解压后打开 `.dmg` |

Windows 安装后无需开发工具。首次运行时将电脑与音响连接同一局域网，并在防火墙提示中允许此应用访问私人网络。优先用一首本地 MP3 验证发现和播放，再测试 Bilibili 导入、曲名修改与曲库移除。

当前配置未包含发行证书或 Apple 公证。面向他人分发前，可按 [Windows 签名](https://v2.tauri.app/distribute/sign/windows/)与 [macOS 签名 / 公证](https://v2.tauri.app/distribute/sign/macos/)配置证书；本地开发不依赖签名证书。

## 测试

```sh
npm run check:ui
npm run test:ui
npm run test:core
npm test
npm run lint
npm run fmt -- --check
```

核心测试包含真实本地 HTTP / SOAP 模拟音箱、Pro 描述识别、SSDP 响应解析与多目标查询、导入持久化、文件身份检查、媒体 HEAD / Range / 416、播放控制、队列结束判断及服务关闭；另外覆盖语音作用域、时间过滤、重复记录、歌名歧义、目标音响绑定、Bilibili WBI 签名、音轨选择、真实 HTTP 下载队列、取消重试、残缺内容拒绝、凭据域隔离与下载来源持久化。不会向真实音箱发送播放命令。

## 连接排查

使用 FlClash 时，先参考 [国内直连 / 海外代理与网络排障](docs/FLCLASH_NETWORK.md)，区分系统代理、原生请求、TUN 与局域网投屏路径。

**搜索不到音箱**：确认已开启 DLNA、处于同一局域网，避免访客 Wi-Fi、AP 隔离；暂时断开影响本地路由的 VPN。自动发现使用 UDP 组播 `239.255.255.250:1900`。可手动添加 SSDP `LOCATION` 中的完整设备描述 URL，只有 IP 地址不够，端口与路径不能猜测。

**找到设备但不能播放**：允许应用接受局域网入站连接。Windows 防火墙选择私人网络；macOS 允许本地网络访问和入站连接。媒体服务使用随机 TCP 端口，可在界面的诊断信息查看。确认音乐仍在原位置，先用 MP3 排除格式问题。

**进度、音量、自动下一首不可用**：这些操作依赖音箱的 UPnP 服务。只有正常获得播放、进度与结束状态时才自动续播；停止、定位读取失败或检测到其他控制器接管时不会依据旧进度自动切歌。歌曲过短或不报告时长时可手动切歌。

## 数据与访问范围

音乐库索引存放在系统应用数据目录中的 `com.localmusic.xiaomi-dlna/library.json`，macOS 通常在 `~/Library/Application Support/` 下，Windows 通常在 `%APPDATA%` 下。原文件留在导入位置。Bilibili 下载音频由应用保存在同目录下的 `downloads/`，索引中保留来源链接；只记录所选公开视频页，不记录带签名的临时下载地址。

播放、曲库管理及账号设置使用本地桌面 IPC。媒体 HTTP 服务提供带随机会话令牌的已导入歌曲，支持单段 Range，应用重启后旧音乐链接失效。用户主动开启“手机发送”时，另一个独立局域网入口仅提供配对、视频解析、所选音轨下载及本次任务状态；暂停或重启会停止接收但保留手机配对；“忘记手机”清除配对。设备描述和控制地址仅允许本机 / 局域网地址，不跟随重定向，不使用系统代理。

## 代码结构

```text
frontend/                 中文桌面界面
mobile/                   免安装手机发送页面（编译进桌面应用）
src-tauri/src/desktop.rs   Tauri 命令、原生选择器、生命周期
src-tauri/src/engine.rs    状态、播放队列、自动发现与轮询
src-tauri/src/dlna.rs      SSDP、设备描述、UPnP SOAP
src-tauri/src/library.rs   本地文件索引与持久化
src-tauri/src/media.rs     带会话令牌的 HTTP 音乐流
src-tauri/src/mobile.rs    主动开启的局域网配对与音乐导入入口
src-tauri/src/voice.rs     小爱会话、新指令轮询与本地命令解析
src-tauri/src/bilibili.rs  视频解析、WBI、音轨下载队列与原子入库
src-tauri/src/online.rs    有界在线响应、Cookie 范围与网络超时
src-tauri/tests/           跨模块真实 HTTP 集成测试
```

`xiaomi_dlna/` 与 `tests/` 保留之前的 Python 版本供参考，不参与桌面应用运行或打包；[旧版说明](docs/LEGACY_PYTHON.md)仅适用于旧版。两者音乐库独立，桌面版请重新导入原音乐文件。
